# 4.6 Scenario 6: BOE Flagging Cadence + Stale Resolution

**Status:** Done
**Priority:** P1  
**Effort:** 3-4 days  
**Depends on:** [2.8 BOE-Driven Automatic Eligibility Flagging](2.8-boe-driven-automatic-eligibility-flagging.md), [4.5 Scenario 5: Resignation Audit Durability + Reason Capture](4.5-scenario5-resignation-audit-durability.md)

## Summary

Tighten BOE eligibility flag operations so queue state reflects current reality, runs are operationally enforced, and confirmed removals remain auditable.

## Acceptance Criteria

### Run Cadence + Orchestration

- [x] BOE eligibility flagging is triggered after voter imports and on a scheduled recurring run (nightly or documented equivalent).
- [x] Run scheduling is encoded in job orchestration/config, not manual operator memory.

### Stale Pending Resolution

- [x] Re-scan logic auto-resolves stale `PENDING` flags when the triggering condition is no longer present.
- [x] Auto-resolved items are marked with explicit resolution metadata (for example `RESOLVED_BY_RESCAN`) and timestamp.
- [x] Queue views separate active pending work from auto-resolved historical entries.

### Audit Consistency

- [x] Confirm-removal decisions from eligibility flags follow the same audit durability policy as Ticket 4.5.
- [x] Audit entries include flag id, reason, decision, and reviewer/system actor context.

### Tests

- [x] Processor tests verify stale flag auto-resolution behavior.
- [x] Integration test verifies scheduled or orchestrated rerun path executes flagging without manual API trigger.
- [x] API tests verify audit payload completeness for confirm and auto-resolution paths.

## Implementation Notes

- Added recurring BOE eligibility re-scan scheduler in report-server orchestration:
  - default enabled (`BOE_FLAGGING_RESCAN_ENABLED=true`)
  - default cadence every 24 hours (`BOE_FLAGGING_RESCAN_INTERVAL_HOURS=24`)
  - configurable startup delay (`BOE_FLAGGING_RESCAN_INITIAL_DELAY_MINUTES`)
  - optional term override (`BOE_FLAGGING_RESCAN_TERM_ID`)
- Extended eligibility processor to auto-resolve stale pending flags:
  - new lifecycle status: `RESOLVED_BY_RESCAN`
  - resolution metadata stored in `EligibilityFlag.details`:
    - `resolution=RESOLVED_BY_RESCAN`
    - `resolutionTimestamp`
    - `resolvedByActor=system`
  - `reviewedAt` and `reviewedById` are set for auto-resolved rows
- Audit consistency hardening:
  - confirm/dismiss review-path audit metadata now includes decision + reviewer context
  - auto-resolution path emits `DISCREPANCY_RESOLVED` with system actor context
- Queue separation:
  - UI default status filter remains `PENDING` (active work queue)
  - `RESOLVED_BY_RESCAN` is exposed as a distinct historical status filter
