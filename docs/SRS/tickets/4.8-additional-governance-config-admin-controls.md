# 4.8 Additional Requirements: Governance Config Admin Controls

**Status:** Done  
**Priority:** P1  
**Effort:** 3-5 days  
**Depends on:** [1.1c Committee Governance Config](1.1c-committee-governance-config.md), [2.1 Eligibility Validation](2.1-eligibility-validation.md)

## Summary

Implement in-app admin management for `CommitteeGovernanceConfig` so party, seat-capacity, AD eligibility toggle, and non-overridable reason policy are operationally configurable and validated.

## Acceptance Criteria

### Admin API

- [x] Add admin-only read/update endpoint(s) for governance config.
- [x] Update validation enforces:
  - `requiredPartyCode` must exist in `DropdownLists.party`.
  - `maxSeatsPerLted` must be a positive integer in configured guardrail range.
  - `requireAssemblyDistrictMatch` is boolean.
  - `nonOverridableIneligibilityReasons` values are valid enum members.
- [x] API returns deterministic validation errors with field-level messages.

### Admin UI

- [x] Add governance-config admin page with form controls for all required fields.
- [x] Party selector uses authoritative dropdown list values, not free text.
- [x] Save flow shows diff/confirmation and success/failure feedback.

### Audit + Safeguards

- [x] Config updates emit an audit event capturing before/after values and actor.
- [x] Application behavior (eligibility/capacity checks) reflects updated config without restart.
- [x] Only one effective config row remains enforceable at runtime.

### Tests

- [x] API tests cover validation success/failure for each field.
- [x] UI test covers load/edit/save flow and error handling.
- [x] Integration test verifies updated config changes downstream eligibility/capacity behavior.

## Implementation Summary

- Added admin governance-config API: `GET/PATCH /api/admin/governance-config` with strict validation and field-level deterministic errors.
- Added governance config validation module with explicit seat guardrails and enum-safe parsing.
- Added admin UI at `/admin/governance-config` with:
  - authoritative party selector from `DropdownLists.party`
  - complete form controls for all `CommitteeGovernanceConfig` fields
  - pending-change diff preview + explicit confirmation step before save
  - inline validation errors and save failure/success feedback
- Added governance-config audit logging with before/after snapshots and actor context.
- Hardened runtime selection of governance config to deterministic latest row and defensive singleton enforcement on update.
