# 4.7 Scenario 7: Leader Reports Scope Hardening + Roster Export

**Status:** Done  
**Priority:** P0/P1  
**Effort:** 3-5 days  
**Depends on:** [3.0a Report Audit](3.0a-report-audit-committee-membership.md), [3.1 Jurisdiction Assignment UI](3.1-jurisdiction-assignment-ui.md), [3.2 Sign-In Sheet Report UI](3.2-sign-in-sheet-report-ui.md), [3.3 Designation Weight Summary Report UI](3.3-designation-weight-summary-report-ui.md)

## Summary

Close Scenario 7 by delivering a leader-safe roster generation path and hardening report authorization/scope enforcement at the API boundary.

## Acceptance Criteria

### Leader Roster Generation

- [x] Add a leader-accessible "current committee roster" report flow (PDF and/or CSV per approved requirement wording).
- [x] Roster report is jurisdiction-scoped for leader users and only includes authorized committees.
- [x] UI exposes this capability from leader workflows without admin-only navigation.

### API Auth + Scope Hardening

- [x] `/api/generateReport` enforces role/scope restrictions server-side for all report types, including `ldCommittees`.
- [x] `ldCommittees` is admin-only unless a dedicated jurisdiction-scoped leader variant is introduced.
- [x] Direct API invocation by leader cannot produce countywide output.

### Requirement/Format Alignment

- [x] SRS wording is aligned with implemented export formats (PDF/CSV/XLSX as applicable).
- [x] Report parameter matrix documents final format support per report type.

### Tests

- [x] API tests verify role/scope boundaries for `ldCommittees` and new roster report flow.
- [x] UI tests verify leader can generate allowed reports and cannot trigger blocked scopes.
- [x] Report-generation mapping test verifies roster output schema used by PDF/XLSX generation.

## Implementation Notes

- Added new scoped report type: `committeeRoster`.
  - Leaders can generate jurisdiction-scoped roster reports.
  - Admins can generate countywide or jurisdiction-scoped roster reports.
- Added leader-facing roster UI flow at `/committee-roster-reports` and wired entry points from:
  - Reports dashboard card grid
  - Committee workspace "Generate Committee Roster Report" button
- Hardened `/api/generateReport`:
  - `ldCommittees` explicitly restricted to admin users
  - `committeeRoster` enforced through existing jurisdiction validation path (leaders cannot request countywide)
- Extended report-server processing:
  - Added scoped roster fetch helper (`fetchCommitteeRosterData`)
  - Added `committeeRoster` processing branch reusing committee PDF/XLSX generation pipeline
- Updated report type mappings and schema unions so the new type is valid end-to-end.
