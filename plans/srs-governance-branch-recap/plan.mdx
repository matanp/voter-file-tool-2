### What this branch does

`feat/srs-implementation` is a large, multi-tier build (111 commits, 333 files,
~41k insertions over merge-base `ecfcf74`) that re-platforms committee management
onto the formal **SRS** requirements. The center of gravity is a new
**`CommitteeMembership`** record — the authoritative, never-deleted link between a
voter and a committee that moves through a status lifecycle
(`SUBMITTED → CONFIRMED → ACTIVE`, with rejection/resignation/removal/petition
terminal states) — which supersedes the old `VoterRecord.committeeId` foreign key
(deprecated, removal deferred to ticket 3.0).

Around that core the branch adds: an **immutable `AuditLog`** for every state
change; **`CommitteeTerm`**, **`Seat`**, and **`UserJurisdiction`** for
term-scoped seats and Leader access scope; a **BOE eligibility-flagging engine**
(`packages/shared-prisma/src/boeEligibilityFlagging.ts`) that scans active members
against governance config and the latest BOE import; a **6-report suite**
(committee roster, sign-in sheet, designation-weight summary, vacancy, changes,
petition outcomes); and an **8-section admin console** (Data, Terms, Meetings,
Governance Config, Users, Eligibility Flags, Petition Outcomes, Audit Trail)
behind a new `Leader` privilege level. ~26 Prisma migrations back the schema.
