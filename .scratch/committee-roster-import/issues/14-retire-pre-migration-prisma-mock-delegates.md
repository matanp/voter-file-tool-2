# 14: Retire pre-migration Prisma mock delegate shims

**Status:** ready-for-agent

**Priority:** P2 test-safety hardening. This is not a merge blocker for the roster import branch,
but it is the highest-leverage follow-up from the type-safety review because the schema now has the
models the shims were created to cover.

**What to fix:** `apps/frontend/jest.setup.ts` still injects raw Jest mock objects for Prisma
delegates that are now generated by Prisma:

- `CommitteeMembership` exists in `apps/frontend/prisma/schema.prisma`.
- `CommitteeUploadDiscrepancy` exists in the schema.
- `AuditLog` exists in the schema.
- `Seat` exists in the schema.

The setup comment says the block is temporary until `prisma generate`, but that point has passed.
Assigning raw `jest.fn()` delegates over `mockDeep<PrismaClient>()` erases the generated argument and
return types. The shared helpers `getMembershipMock`, `getAuditLogMock`, and the local `getSeatMock`
patterns then encourage tests to assert against hand-written shapes rather than
`Prisma.*Args`.

## Why this matters

Tests compile even when they stop matching production query contracts. For example, a local
`MembershipFindManyArgs` can describe `where` keys without ever being compared to
`Prisma.CommitteeMembershipFindManyArgs`. If production changes a query key, the test may keep
compiling and simply fail to exercise the branch it meant to cover.

The roster import branch stopped adding the new `getDiscrepancyMock` pattern, but the broader mock
setup still leaves many membership, audit-log, and seat tests behind an untyped facade.

## Suggested migration

- Remove the pre-migration injection block for delegates that Prisma now generates.
- Delete shared raw accessors whose only purpose was to work around missing Prisma types:
  `getMembershipMock`, `getAuditLogMock`, and any discrepancy equivalent.
- Update tests to use `prismaMock.committeeMembership`, `prismaMock.auditLog`,
  `prismaMock.seat`, and `prismaMock.committeeUploadDiscrepancy` directly.
- Where a mock implementation needs an argument type, use generated Prisma types such as
  `Prisma.CommitteeMembershipFindManyArgs` or
  `Prisma.CommitteeUploadDiscrepancyUpdateArgs`.
- Where assertions inspect mock calls, prefer the typed delegate's `mock.calls` when it is usable;
  keep `firstCallArg<T>` only as the centralized escape hatch for call sites that still cannot be
  typed cleanly.

## Acceptance criteria

- [ ] `jest.setup.ts` no longer overwrites generated Prisma delegates for membership, seat,
      discrepancy, or audit-log models with raw `jest.fn()` bags.
- [ ] Tests access those delegates directly from `prismaMock`.
- [ ] Hand-written Prisma delegate argument aliases in tests are replaced by generated
      `Prisma.*Args` types.
- [ ] `getMembershipMock`, `getAuditLogMock`, and any discrepancy mock accessor are removed once no
      callers remain.
- [ ] The frontend type check passes:
      `pnpm --filter voter-file-tool exec tsc --noEmit --pretty false`.

## Out of scope

- Changing production Prisma queries.
- Refactoring tests that use unrelated framework-boundary casts.
